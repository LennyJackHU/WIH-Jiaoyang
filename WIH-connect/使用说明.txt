二、固件准备（烧录由你确认后再做）
1. 硬件必须是 ESP32-S3-DevKitC-1 N8R8：8 MB QIO Flash + 8 MB OPI PSRAM。
2. 用 PlatformIO 打开上述固件工程，不是 firstConnect 子文件夹。
3. 默认环境保持 esp32-s3-devkitc-1-n8r8，先运行 pio run 编译。
4. Windows 建议把工程放在纯英文路径，如 E:\WIH-Web\firmware。
   本机已遇到中文构建路径导致链接器 cannot open map file / Invalid argument；
   详细文档提供经验证的 ASCII 构建目录设置方法。
5. 只有你决定烧录且确认板型、端口后，才执行 PlatformIO Upload。
   烧录前断开网页串口并关闭串口监视器；本次没有自动执行此操作。

三、启动网页
1. 在本工作文件夹运行；若使用完整包，则先进入 web 文件夹。
2. 已有 config.json 时保留原文件，不要覆盖。
   仅全新部署时，把 config.example.json 复制成 config.json，再填写自己的参数。
   原 server.py 启动时会检查 apiKey/baseUrl/model 非空。
   只测串口、不调用 AI 时可用非空测试占位参数；AI 功能需要有效服务配置。
3. 运行：
     python server.py 8000
4. 用桌面 Chrome 或 Edge 打开：
     http://localhost:8000
   不要直接双击 index.html，不要把本地开发服务暴露到公网。
5. 用支持数据传输的 USB 线连接板子的 USB-to-UART 接口，
   不要误接 ESP32-S3 原生 USB 接口。此版保留 CDC_ON_BOOT=0。
6. 关闭 PlatformIO/Arduino 串口监视器和其他占用同一 COM 口的软件。
7. 点击「连接设备」，选择板子的 USB-to-UART COM 口。
   网页固定使用 115200 baud；先显示「等待词块固件」，
   收到周期 ready 帧后才显示「已连接」，通常约 2 秒。

四、使用与边界
1. 板子在 Picker 选词页，旋转编码器选词，第一次按 A 确认：
   网页追加一个词块；如果网页停在首页，会自动进入拼贴台。
2. 再次按 A 仍执行原来的板间传词，不会在网页重复追加。
3. B 取消板上的确认，不撤回已加入网页的词块；请在网页单独删除。
4. 取消后重新确认同一个词是一次新操作，会再追加一次。
5. Sentence 句子页操作、从另一块板收到的词、开机恢复的内容不会逐词导入。
6. 这是“本机确认单词 → 网页”的单向事件连接：
   不回写板子、不同步整句、不补发未连接时的单词；网页和板上句子各自独立。
7. 断线后显示中断状态，重新点击连接并选择串口。
   同一个网页实例按设备/启动会话/序号去重，保留最近 1024 个事件；
   刷新网页后不保留该去重历史。连接一次只监听一块板。
8. 拼好后可以进入缪斯间使用原有评价、故事和学习功能，
   并使用原来的诗集墙功能；这些网页功能没有改写。

五、排查顺序
找不到 COM：检查数据线、USB-to-UART 接口及驱动。
连接失败：关闭占用串口的监视器或其他网页，重试选择正确端口。
一直等待固件：检查是否烧录了本次工程，是否选错接口/端口；等板子启动完成。
已连接但不加词：确认在 Picker 页按的是第一次 A；句子页 A 不产生新选词事件。
网页启动失败：确认 Python 可用、端口未占用、config.json 参数已填写。
AI 出错：单独检查服务配置及网络；AI 与串口连接是两条独立链路。
