# 接线说明 — ESP32-S3-DevKitC-1 × Waveshare 1.54" e-Paper（V2/V2.1 驱动板）

屏幕规格：200×200 黑白，SPI 接口，驱动板 8PIN 排座（2.54mm）。V2.1 驱动板自带电平转换，3.3V 直连即可。屏幕背面有 V2 标签；若实际是 V1 老板（IL0373），需把 `src/display.h` 中的 `GxEPD2_154_D67` 换成 `GxEPD2_154`。

所有硬件固定使用 **N8R8：8 MB QIO Flash + 8 MB OPI PSRAM**，不混用其他 Flash/PSRAM 容量或模式。唯一固件环境及默认环境为 `esp32-s3-devkitc-1-n8r8`，直接运行 `pio run` / `pio run -t upload`（或 `pio upload`），无需 `-e`。这些默认构建和烧录命令**只生成、只烧录 N8R8 固件**；`native` 环境只用于主机测试。配置固定为 `qio_opi`、8 MB 分区和 `BOARD_HAS_PSRAM`。GPIO35–37 专用于存储器，不能接外设；当前 UART/屏幕/编码器引脚不占用这些存储器引脚。

DevKitC PCB 版本仍要区分：RGB LED 在 **v1.1 是 GPIO38、v1.0 是 GPIO48**，可通过 `PIN_RGB_LED` 覆盖；这与固定 N8R8 存储配置是两件事。

## Pogo 邻接 UART（候选引脚，待实板复核）

| 接口 | 控制器 | TX | RX | 连接关系 |
|---|---|---:|---:|---|
| 左邻 L | UART1 | GPIO17 | GPIO18 | 接左侧模块的 R 口 |
| 右邻 R | UART2 | GPIO15 | GPIO16 | 接右侧模块的 L 口 |

两端均为 115200、8N1、3.3V UART；TX 对 RX、RX 对 TX，并必须共地。固件为每口配置 4096 B RX/TX 缓冲并记录 UART 错误计数，BUSY 等待期间继续服务协议。地触点应先接后断；不跨模块连接电池正极、3.3V 或 5V。

以双板 **A.R ↔ B.L** 为例，断电后按下表逐点连接并复核：

| 信号 | 板 A（R 口，UART2） | 方向 | 板 B（L 口，UART1） |
|---|---|---|---|
| A 发送 / B 接收 | GPIO15（TX） | → | GPIO18（RX） |
| B 发送 / A 接收 | GPIO16（RX） | ← | GPIO17（TX） |
| 公共参考地 | GND | ↔ | GND |

这里只需交叉 TX/RX 并共地，不连接两板电源正极。反向使用 A.L ↔ B.R 时也按各口引脚表交叉连接，不要把两个 TX 或两个 RX 直接相连。

### 开放身份与冲突恢复

1. 不需要预配置 member 白名单。首次启动由 MAC 派生 64 位节点 ID 和设备指纹；相同 `WIH_KIT_ID` 且使用 WLP2 v3 的陌生模块可在物理接触后直接握手。
2. 同设备重启保留节点 ID 和指纹，只更新 boot ID。不同设备节点 ID 相同但指纹不同时会触发双方随机换号、退避和重新 HELLO。
3. 新 ID 通过 NVS `wih/node_id` 保存，重启继续使用；启动日志 `wlp2: reassigned id=... saved=1` 可用于核对。若再次冲突会继续换号。
4. 两块板仍需同步到同一固件提交并使用相同 `WIH_KIT_ID`。旧 v2 白名单固件不能与 v3 混合验收。开放加入不提供密码学认证，详见 [开放加入与冲突恢复](open-join.md)。

**直连 GPIO 不等于可安全带电插拔。** 原型每个 L/R 邻接口建议使用一片 SN74LVC2G125：两个通道分别隔离本机 TX 和远端 RX，`/OE` 默认上拉禁用，信号串联约 220Ω，缓冲器输入及 MCU RX 用 10k～47kΩ 上拉保持空闲高，触点旁增加低电感 TVS 回流。地触点必须以机械 first-mate/last-break 保证先接后断，镜像和 TX/RX 逐点导通验证。阻值只是调试起点，不是厂家指定值；`Ioff` 只保证器件 VCC=0V 时的高阻/漏电特性，不保证所有电源斜坡和系统级 ESD。

必须实测单侧掉电倒灌、慢/快电源斜坡、`/OE` 波形、单线断开、接触抖动和触点 ESD。通过这些之前只能说“协议支持重连”，不能说“电气上支持安全热插拔”。官方器件依据包括 ESP32-S3/DevKitC-1 数据手册、ESP32 硬件设计指南和 TI SN74LVC2G125 数据手册；社区 UART 倒灌案例仅作风险旁证。

## 交互逻辑

- **Picker**：编码器双向无终点选词，相邻词不重复。A 第一次选中、第二次向唯一直接邻居 offer；B 在未选中时 shuffle、已选中时取消。长按 A 弹单机模式确认。
- **Sentence / Navigate**：下划线标记选择 cursor。A 进入竖线插入模式；短 B 弹删除当前词确认，长 B 弹清句确认。
- **Sentence / InsertCursor**：竖线表示插入位置，编码器在句首、词间和句尾移动。A 返回选择模式，B 取消插入模式。
- **物理左右与句内位置**：选择模式下无 `pos` offer 按 Left 到句首、Right 到句尾；插入模式下无 `pos` offer 落在竖线处。带 `pos` 的消息始终按指定位置插入，换向重连不搬动已插入的词。
- **单机和上传**：单机 Picker 第二次 A 插入本机当前词。非空 Sentence 长按 A 经确认后通过 UART0 上传冻结整句；所有确认页 A 确认、B 取消。
- **完成与重试**：发送方收到应用层 ACCEPT 后才重新随机。运行中断线保留 req 重试且不重复插入；B 取消本机 pending 不远程撤销对端内容。
- **持久化边界**：WIH5 保存句子顺序、选择 cursor、竖线位置、单机标记、来源和 receipts；确认页与 offer/pull pending 不保证跨断电恢复。
- **刷新与持续监听**：滚动使用快速局刷，每 20 次局刷自动全刷一次；无操作约 5 秒后只让墨水屏 hibernate，MCU 不深睡，UART、`game.tick()` 和重试持续运行。

完整模式切换、按键上下文、上传格式和协议时序见 [句子编辑器说明](sentence-editor.md)。

## 按钮（开机自动识别每个引脚的触发极性）

不同批次的按钮模块电气特性可能不同（有的空闲为高、有的空闲为低）。固件开机采样 60ms 自动判定：空闲读高 → 低电平触发并启用上拉；空闲读低 → 高电平触发并启用下拉。**开机瞬间请勿按住按钮**（自锁按钮请先确保处于弹起态）。低有效按钮需要确定的上拉，高有效按钮需要确定的外部下拉；不支持无外部上下拉的悬空输入。

| 按钮 | DevKitC-1 | GPIO | 功能 |
|---|---|---|---|
| A | 7 | GPIO7 | Picker 选中/发送或本机入句，长按单机确认；Sentence 切换选择/竖线模式，长按上传确认；确认页确认 |
| B | 8 | GPIO8 | Picker shuffle/取消；Sentence 短按删除确认、长按清句确认、插入模式取消；确认页取消；pending 时优先取消本机请求 |

只有屏幕+单按钮的板子：按钮接 GPIO7 即可，GPIO8 留空。

屏幕休眠后不需要按 A 唤醒 MCU，因为 MCU 始终保持运行。本地按钮、编码器、Pogo 连接或有效来词产生内容变化时，屏幕会重新初始化并先全刷；即时 OFFER/PULL 不等屏幕恢复，也不依赖额外按键。

## 使用注意（来自微雪手册）

- 局部刷新连续多次后需全刷一次（固件已每 20 次局部刷新自动全刷）；多位置局刷后若字体变浅，改为每 5 次全刷并复测。
- 无操作约 5 秒且画面更新完成后，屏幕 hibernate 以保护面板。此后串口仍应持续输出 `alive`，UART 保持监听；屏幕已休眠且无绘制变化时不会反复写 NVS。
- 连接、来词或本地输入后的第一次重绘必须全刷。实板验收应覆盖超过 5 秒后的 Pogo 即时握手和传词，不再执行“按 A 唤醒 MCU”流程。
- FPC 排线脆弱，调试时先固定排线；长期存放前先清屏。完整约束与验收见 `docs/display-design-requirements.md`，双板同步流程见 `docs/hardware-sop.md`。
